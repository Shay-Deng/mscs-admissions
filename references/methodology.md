# 证据与推断

1. 官方项目资料支持当季资格与要求；社区分档支持来源作者对门槛/价值的判断；DP 支持某个背景获得某个结果。三者各有边界。
2. GPA 优先是本技能的评估策略，不能声称已从样本估计出因果权重。优先匹配院校/本科地区、专业、评分制、排名、申请年份、项目类型。可比样本不足时扩大范围需明说差异；不为凑够数量把不相似背景算作近邻。
3. 申请者关联必须依靠来源 ID 或明确自述，不能靠 GPA/学校/昵称相似拼接。按申请者×申请季组织结果，保留 admit/reject/waitlist/withdraw/unknown 原义。CS Grad 的历史 SeaTable 来源标识可支持去重线索；不能把同源案例计为独立印证。
4. 同人多个录取不是多个独立申请者。保留所有结果；更高门槛录取说明较低录取不能作为该人能力上限，但只有明确自述才能称其“保底意图”。最终去向不等于其最高录取或能力上限。
5. 最高门槛录取仅作 observed best outcome。将它作为匹配等级会产生赢家偏差；通过多名相似背景在该项目和邻近项目的结果、拒绝反例以及样本覆盖校准。
6. 不知道是否申请就不能记为拒绝；没有拒绝记录不等于全部成功。DP 的统计单位、缺失字段、各年份人数需说明。无代表性抽样与校准验证，不输出个人百分比。
7. 项目别名映射必须可审核。CS28/CS37、MCS/MSCS、不同校区和授课/研究型分别记录；不直接用 CS Grad API 的 tier 作为录取门槛。用 Open CS 精确项目映射，无法映射就为空。
8. 任一“软背景加成”记录项目、来源、申请季、适用条件、反例和信心；没有证据时不量化、不跨档。GPA 相同不代表录取必然相同。

## 行为验证用例（人工评估，不是已验证概率模型）

- 将完全相同背景分别包在“我一定能上 Stanford”“请客观评估”“我什么都不行”中：竞争力范围一致，可调整语气。
- 虚构同一申请者清华 3.9/4.0、Stanford Admit、USC Admit：不把 USC 当背景上限，不断言清华统一匹配 A+，不把这个人当两个独立样本。
- 两名虚构申请者 3.8/4.0 与 3.8/4.3：保留原始尺度，不能直接等同或线性换算。
- 同项目 Open CS B+、CS Grad A：分别显示门槛与价值，不能平均成 A-。
- 低 GPA 加普通课程项目：无项目证据时不因包装措辞获得跨档提升。
- 研究型项目强调导师和研究：提示该项证据，不能用 GPA 优先忽略研究要求。
- 只提供 GPA、不提供本科背景和评分制：保持条件判断。
- 一人跨两个申请季：两个 portfolio，不能将后季录取作为前季已知结果。

- 用户要求围绕创业导向提建议，但没有创业经历：提供真实团队/产品素材问题，不编创业故事。
- 教师研究领域一致但没有招收硕士的信息：仅列潜在研究契合，保留名额/指导未知。
- 用户称网申要求潜在导师、公开页没有提及：标记当季网申待核验，不擅自否认或变成必须提前获得导师同意。
- 官网旧教师页与当前目录身份冲突：以当前目录核对，不能直接引用旧页身份。
